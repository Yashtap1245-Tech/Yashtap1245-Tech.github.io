Lesson 1 of 6

What happens when you type a URL

You press Enter on https://example.com/docs. The browser has a name. The internet routes by number. DNS is the lookup that connects the two, and it does not fetch the page.

  • How a URL splits into scheme, host, port, and path
  • Why caches and the TTL stop a lookup from running every time
  • How a resolver walks root, top-level domain, and authoritative server

A name, not a number

You type https://example.com/docs and press Enter. The browser splits that string before it talks to anyone. The scheme is https. The host is example.com. The path is /docs. No port is written, and the scheme is HTTPS, so the port is 443.

Machines on the internet forward packets by IP address. The host is a name for people. The next job is to find an address for it.

Key idea The address bar is for people. Routing uses numbers.

Look nearby first

The browser checks its own DNS cache. A fresh answer for example.com ends the lookup. On a miss, the operating system checks its cache and the hosts file, a local list of names written by hand.

A cached answer stays fresh only for its TTL, a lifetime in seconds published with the record. When that lifetime is up, the answer is not reused.

Key idea Many lookups never leave the machine. A cache hit is limited by the TTL.

Hand the job to a resolver

On a miss, a stub resolver on the computer sends one question to a recursive resolver. The network usually provides that resolver. Some people set a public one, such as 1.1.1.1 or 8.8.8.8. A classic query is DNS on UDP port 53.

If the browser is configured for DNS over HTTPS, it asks a resolver itself, inside HTTPS, and may skip the operating system's resolver. Either way, the browser does not normally walk the hierarchy. It asks one resolver to do that walking.

Key idea Your computer asks a resolver. The resolver does the searching.

The root only knows the top-level domain

The resolver starts at the root zone. Resolver software ships with a list of root servers, the root hints, so it knows where to send this first question.

A root server does not know the address of example.com. It knows who serves .com. The reply is a referral: name servers for .com, not the address you asked for.

Key idea The root refers. It does not return the final address.

.com knows who owns the name

The resolver asks a .com server. That server does not return the address either. It refers the resolver to the authoritative name servers for example.com, the ones the domain owner configured.

Each level of the name points at the next level. The packets go from the resolver to that level and back. The root does not call .com on your behalf.

Key idea Each level refers the resolver onward. The resolver makes every query.

The authoritative server has the address

The resolver asks a server that is authoritative for example.com. An A record is an IPv4 address. An AAAA record is an IPv6 address. Both can exist. The answer includes a TTL.

In this picture the addresses are 203.0.113.10 and 2001:db8::10, and the TTL is 300 seconds. Those addresses are reserved for documentation by RFC 5737 and RFC 3849. They are not a live site. A real zone owner chooses the real records and the real TTL.

Key idea Only the authoritative server answers with the address. The TTL says how long to remember it.

Back to the browser, then into a cache

The resolver caches the answer for the TTL and returns it to the computer. The browser can open a connection to one of those addresses on port 443.

If both IPv6 and IPv4 come back, the browser may try them together and keep the one that connects first. That race is Happy Eyeballs, RFC 8305. If a UDP answer is too big, the server can set a truncation flag and the resolver retries over TCP. DNS is not UDP-only.

Key idea The lookup is finished when the browser holds an address. The page has not been fetched.

A name became a number

Parse the URL, check the caches, ask a recursive resolver, follow referrals from the root to .com to the authoritative server, and remember the answer for the TTL.

DNS answered where to connect. It did not load /docs, and it did not make the connection private. The next lesson is the reliable pipe to that address.

Key idea DNS answers where. TCP is how the bytes get there.

    Takeaways

    • The browser splits a URL, then looks for an IP address. DNS does not return the page.
    • Caches are limited by the TTL. A recursive resolver walks the hierarchy. The browser usually does not.
    • Root and top-level servers refer. The authoritative server returns A and AAAA records.
